# Free Marketplace launch

repo-steward will launch with one permanent free plan. Paid plans are out of scope until
the App is organization-owned, its publisher is verified, and it has at least 100
installations.

## Registration

Create the GitHub App registration before the first Render deployment so Render can
receive the App ID and private key. During bootstrap, use
`https://github.com/khlaifiabilel` as the homepage, leave the setup URL blank, and disable
the webhook. After Render assigns the production HTTPS origin, replace `YOUR-HOST` below
with that origin and activate the webhook.

| Field | Value |
| --- | --- |
| GitHub App name | `repo-steward` or the closest available unique name |
| Description | `Deterministic, read-only repository health checks for maintainers` |
| Homepage URL | `https://YOUR-HOST/` |
| Callback URL | Leave blank until user authorization is implemented |
| Setup URL | `https://YOUR-HOST/` |
| Webhook URL | `https://YOUR-HOST/webhooks/github` |
| Webhook secret | A unique random value of at least 32 characters |
| SSL verification | Enabled when the webhook is activated |
| User authorization | Disabled until the authenticated installation UI exists |
| Installation scope | Any account |

Request only these repository permissions:

- **Metadata:** Read-only (required by GitHub)
- **Contents:** Read-only

GitHub Apps receive `installation` and `installation_repositories` lifecycle events
automatically. Do not add optional event subscriptions during staging. Add `push` only
after explicit re-analysis orchestration and delivery idempotency are implemented.

The Marketplace listing must also deliver `marketplace_purchase` events to the configured
webhook so purchases, plan changes, pending changes, and cancellations are observed. The
single free tier does not require entitlement persistence, but every event is signature
checked and schema validated.

Generate a private key only for the production deployment. Store the App ID, private key,
and webhook secret in the hosting platform's secret manager. Never commit or paste them
into logs, issues, support requests, screenshots, or Marketplace listing text.

## Deployment contract

The container expects an HTTPS reverse proxy or managed container platform. At minimum,
configure:

```text
REPO_STEWARD_ENVIRONMENT=production
REPO_STEWARD_API_KEY=<random value of at least 32 characters>
REPO_STEWARD_GITHUB_APP_ID=<registered App ID>
REPO_STEWARD_GITHUB_PRIVATE_KEY=<PEM value supplied through the secret manager>
REPO_STEWARD_GITHUB_WEBHOOK_SECRET=<random value of at least 32 characters>
```

The deployment must provide TLS, health checks against `/healthz`, bounded log retention,
secret rotation, request-size limits at the edge, and monitoring for webhook failures.
Verify these public URLs before creating a draft listing:

- `https://YOUR-HOST/`
- `https://YOUR-HOST/privacy`
- `https://YOUR-HOST/terms`
- `https://YOUR-HOST/support`
- `https://YOUR-HOST/healthz`

### Render staging deployment

The repository includes `render.yaml` for a free Render web service in Frankfurt. It
builds the existing Dockerfile, keeps one instance, checks `/healthz`, and disables
automatic deployments so a push cannot release unreviewed code. This free service is for
staging only: it can sleep while idle, delay webhook responses during startup, and does not
meet the availability requirements of a published Marketplace app.

1. Create the GitHub App registration with the temporary homepage above, webhooks inactive,
   read-only permissions, and installation allowed on any account.
2. Generate the App private key and a separate random webhook secret of at least 32
   characters. Keep both outside the repository.
3. Connect Render to GitHub and grant it access only to the private `repo-steward`
   repository.
4. In the Render Dashboard, create a Blueprint from the repository's `main` branch.
5. Confirm that Render shows the `free` plan and no payment before approving creation.
6. Supply the App ID, private key, and webhook secret only through Render's prompted secret
   fields. The API key is generated by Render.
7. After the first deploy, use the assigned `onrender.com` origin for the GitHub App URLs,
   enable the webhook with SSL verification, and send a test delivery.
8. Keep automatic deployments disabled until GitHub Actions executes successfully. Deploy
   reviewed commits manually in the meantime.

Before Marketplace publication, move the service to reliable always-on infrastructure and
repeat the webhook latency, redelivery, and recovery tests. Marketplace pricing can remain
free even when its infrastructure is paid.

Do not create the Blueprint before the GitHub App registration values are ready: Render
only prompts for `sync: false` secrets during initial Blueprint creation. If the service
already exists, add new secrets manually in the Render Dashboard.

Review a consistent score and concrete findings across documentation, community files,

## Publication gates

Do not submit the listing for review until all gates pass:

- Production CI and dependency updates execute successfully.
- A public production deployment is monitored and has passed webhook redelivery tests.
- Installation-aware enumeration uses each installation's short-lived token and passes
  scope-isolation tests.
- An authenticated installation report experience is available to every installer.
- Webhook delivery idempotency and operational failure recovery are implemented.
- Privacy, terms, support, security, and subprocessor information match production.
- A square logo of at least 200 by 200 pixels, a 965 by 482 pixel feature-card
  background, and consistent screenshots at least 1200 pixels wide are reviewed.
- The draft listing is public, includes the free pricing plan, and is not invite-only.
- The GitHub Marketplace Developer Agreement has been reviewed and accepted by the owner.

The current API and public pages are launch foundations, not authorization to submit the
listing. In particular, the operator API key is not an installer authentication mechanism.
